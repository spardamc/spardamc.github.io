FAQ

Getting started

The mod loaded but there are no quests

That is expected. Scripta ships three starter categories — Getting Started, Combat Basics and Exploration — but zero quests. Quests are yours to author. Start in the quest reference or just use an editor.

Do I need to install OwoLib?

No. OwoLib is bundled inside the Scripta jar. Installing a separate OwoLib jar will trigger a duplicate-mod error — use one or the other.

Do players need the mod?

Yes, on a multiplayer server. The quest book renders client-side, so anyone who joins must install the Scripta client jar as well.

Does it work on NeoForge?

Not yet in 1.0.0. The release ships on Fabric for Minecraft 1.21.1. NeoForge support is retained in the codebase but is not part of the released build.

Authoring

My quest does not appear

Check, in order:

  1. Its category points at a category id that exists.
  2. Its id is unique — a later file with the same id overwrites the earlier one.
  3. You ran /reload after editing files by hand.
  4. Look in the server log for [scripta] Loaded N quest(s) and any Quest parse error lines.

A malformed quest is skipped with an error rather than breaking the load, so the log is the fastest way to find the problem.

Why is my quest locked?

Something in its prerequisites is not completed. Prerequisite ids are not validated when the quest loads, so a typo leaves a quest permanently locked with no warning. Verify each id exists.

Does the file name have to match the id?

No. The id inside the JSON is what matters; the file name is only used in error messages. You can reorganise your folders freely.

Can objectives be optional or hidden?

No, not in 1.0.0. Every objective on a quest must be satisfied to complete it, and every objective is shown. Alternatives are best expressed as separate quests with shared prerequisites, or with a choice reward.

My collect_item quest un-completed itself

collect_item reads your current held count, so dropping the items drops the counter below the requirement. If the goal should stay done, use break_block or kill_entity, which latch at the required count and never decrease.

My reach_stat objective never completes

Only custom stats are supported — ids like minecraft:jump, minecraft:walk_one_cm is not one. An unknown stat simply reads as 0 forever, with no error.

Rewards

When do I get my rewards?

With the default auto_claim: true, everything except choice rewards is granted the instant the quest completes. Set auto_claim to false to require the player to press Claim instead. choice rewards always need a manual pick.

My inventory is full — did I lose the items?

No. Item rewards that do not fit are dropped at your feet.

The editor rejects my reward table entry

Common causes:

  • A choice reward inside a table — not allowed. Put choices on quests.
  • An entry with weight <= 0 — every saved table entry needs a positive weight.
  • A table with no entries at all.
  • A loot_crate pointing at a table without crate.enabled.
  • A value out of range — see the limits table in validation rules.

My reward table is not loaded after /reload

Reward tables are not datapack files. They live in the editor store, so /reload will not pick up a hand-written .json table — create the table in an editor instead. See Files & storage.

How does random differ from loot_crate?

random rolls immediately when the quest completes. loot_crate hands over a physical crate item the player opens whenever they like — which works well as a delayed reward or a collectible.

Does loot crate crate.name do anything?

It is stored but not used. Crate messages use the table's top-level name, falling back to its id.

Web editor

Where do I get the link?

Either way:

  • Operators get it automatically in chat on join.
  • Run /scripta web (operator level 2) and click the link.

I lost the link — where is it in the log?

It is not in the log. Scripta never prints the token. Use /scripta web, or rejoin as an operator. The token also changes every server restart, so old links stop working by design.

/scripta web says the editor is not running

The port could not be bound — usually another process already has 25566. Check the log for [scripta] Could not start web editor on port … and change it with -Dscripta.webport=<port>.

Is it safe to expose the editor to the internet?

Not without care. The token is the only protection, it is sent in the URL, and anyone holding it can rewrite your quests. Keep it on localhost or a private network, or put it behind a reverse proxy with authentication.

Can I edit from a phone?

The web editor is responsive and adapts to narrow screens, so it works on mobile browsers. The in-game editor does not have a mobile equivalent, obviously.

Progress & sync

How do I reset a player?

Run /scripta reset <player> as an operator. The player must be online.

Reset is not a full wipe Reset clears completed quests and objective counters, but keeps the record of which rewards were already claimed. A player who had claimed a manual-claim reward will still see it as claimed. For a truly clean slate, delete scripta_progress.dat with the server stopped.

My quest book looks out of date

Run /scripta sync. That re-sends both your progress and the quest definitions.

Does progress carry between worlds?

No. Progress is per-world by design — quest content is global, but completion state is not.

I deleted a quest. Why is it still in my completed list?

It should not be — deleting a quest prunes it from every player's completed list on the next tick. If it lingers, run /scripta sync to refresh your client.

Where is progress saved?

In the overworld's SavedData at <world>/data/scripta_progress.dat. See Files & storage.

Troubleshooting

The mod will not load

  • Confirm Minecraft is exactly 1.21.1.
  • Confirm Fabric Loader is 0.16.9 or newer.
  • Confirm Fabric API and Architectury API are both installed.
  • Remove any separate OwoLib jar — it is already bundled.

The web editor page loads but says 403 Bad or missing token

The token in the URL does not match. Re-copy the link from chat — the server has most likely restarted, which rotates the token.

My theme change did nothing

  • Check the surface name for typos — unrecognised values fall back to PANEL silently.
  • Check colours are valid 32-bit values if you hand-edited the file.
  • Confirm you saved — an unsaved theme is never broadcast.

A quest shows up as Unknown reward

The quest uses a reward type this version does not know. Scripta keeps it intact rather than discarding the quest, so it will start working correctly once the server runs a version that supports that type.

Reading the server log

Scripta prefixes its messages, so you can filter for them:

[scripta] Loaded 12 quest(s) from datapacks. [scripta] Loaded 3 quest categor(ies) from datapacks. [scripta] Quest parse error in <namespace>:<path>: <reason> [scripta] Skipping bad reward: <reason> [scripta] Could not start web editor on port 25566: <reason>
